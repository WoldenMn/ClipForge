# Correctif CI : ffmpeg absent du runner

**État** : appliqué le 2026-09-26 par la PR #7 (`3e15552`, dans `main`). Ce document garde la cause et la reproduction ; la section « Appliquer » décrit la procédure telle qu'elle était à l'écriture.
**CI rouge depuis** : 2026-09-10. **Cause établie par reproduction locale le 2026-09-20.**

## Cause racine

Le job `backend` échoue sur un seul test, `test_montage_actif_produit_un_concat`.
Le runner `ubuntu-latest` ne fournit plus `ffmpeg`. Sans lui :

- `scripts/make_fixture.py` ne peut pas générer `tests/fixtures/fixture.mp4` ;
- 4 tests qui en dépendent sont skippés ;
- le pipeline de rendu bascule sur un layout par défaut au lieu de produire une
  vraie coupe, donc `assert 'concat=' in filter_complex` tombe.

Le message d'erreur ne nomme jamais ffmpeg : il parle d'un `filter_complex` qui
n'a pas la forme attendue. C'est pourquoi la lecture du log seul n'y menait pas.

## Reproduction, les deux bornes

| Condition | Résultat |
|---|---|
| fixture générée **et** ffmpeg présent | 562 passed |
| ni l'un ni l'autre | 1 failed, 561 passed — même test, même message |

Un seul des deux cas n'aurait rien prouvé : un test qui échoue toujours est
indiscernable d'un test qui échoue pour la raison qu'on croit.

## Le correctif

Six lignes dans `.github/workflows/ci.yml`, entre `Lint` et `Tests unitaires` :

```diff
         run: uv run ruff check .
+      - name: Installer ffmpeg
+        # Le runner ubuntu ne fournit plus ffmpeg. Sans lui, make_fixture.py
+        # ne peut pas generer tests/fixtures/fixture.mp4 : 4 tests sont
+        # skippes et test_montage_actif_... echoue, le pipeline produisant un
+        # layout par defaut au lieu d'une coupe.
+        run: sudo apt-get update && sudo apt-get install -y --no-install-recommends ffmpeg
       - name: Tests unitaires
```

## Appliquer

🔴 **Partir de `origin/main`, jamais de la branche locale.** `docs/review-and-memory-trim`
a 3 commits de retard sur `origin/main` et 1 commit d'avance qui lui est propre ; elle précède
l'épinglage des actions par SHA (commit `bf0dae2`, ancêtre d'`origin/main`). Travailler dessus
rétablirait des actions non épinglées.

```bash
git fetch origin && git switch -c fix/ci-ffmpeg origin/main
```

Puis appliquer le diff ci-dessus et vérifier que le fichier de départ est bien
celui qui a été analysé :

```bash
git rev-parse HEAD:.github/workflows/ci.yml
```

Doit rendre `a893f636e50e77c453d7760fd30b46deb5c71c85`, valeur relevée sur `origin/main`
au fetch du 2026-09-20 21:22. Une autre valeur signifie que le workflow a changé depuis :
refaire le diff plutôt que l'appliquer à l'aveugle.

Sous Git Bash, préfixer par `MSYS_NO_PATHCONV=1` : sans cela le shell réécrit le `:` en `;`
et les `/` en \, et git répond « ambiguous argument ». PowerShell n'a pas ce défaut.
